# Update — June 5, 2026

## Fix 1: Domain Re-detection After sudo Stripping

### Symptom

`sudo git -C /path/to/repo status` was classified as `unknown command` instead of being recognized as a read-only git command.

### Root Cause

`Resolve-Command` strips the `sudo` prefix and recursively re-classifies the remaining command — but it passed the original domain (`linux`) instead of re-detecting the domain from the stripped command. Since `git status` patterns live under the `Git` domain, not `Linux`, the git subcommand was never matched.

### Fix

`src/Resolver.ps1` — After sudo stripping (Step 0c), the domain is now re-detected via `Get-CommandDomain` before the recursive call:

```powershell
$redetectedDomain = Get-CommandDomain -Command $remainingCommand
return Resolve-Command -Command $remainingCommand -Domain $redetectedDomain -Config $Config
```

This correctly routes `sudo git ...` → `git` domain, `sudo docker ...` → `docker` domain, etc.

## Fix 2: Git Global Option Stripping (`-C`, `-c`, `--git-dir`, etc.)

### Symptom

`git -C /opt/repo status` and `git -C "C:\Program Files\repo" log --oneline` were classified as `unknown command` instead of matching existing `git status*` and `git log*` patterns.

### Root Cause

Git supports global options (`-C <path>`, `-c <name=value>`, `--git-dir`, `--work-tree`, `--namespace`, `--exec-path`) that appear before the subcommand. The classification patterns expected the subcommand immediately after `git`, so `git -C /path status` did not match `git status*`.

Additionally, the simple token-splitting approach broke on quoted paths containing spaces (e.g., `"C:\Program Files\repo"`).

### Fix

`src/Resolver.ps1` — New Step 0d strips git global options using regex patterns that handle both quoted and unquoted values:

```powershell
$val = '("[^"]*"|''[^'']*''|\S+)'
do {
    $prev = $stripped
    $stripped = $stripped -replace "^\s*git\s+-C\s+$val\s+", 'git '
    $stripped = $stripped -replace "^\s*git\s+-c\s+$val\s+", 'git '
    $stripped = $stripped -replace "^\s*git\s+--(git-dir|work-tree|namespace|exec-path)=?$val\s+", 'git '
} while ($stripped -ne $prev)
```

This strips options in a loop (handling multiple stacked flags like `-c user.name=foo -C /path`) and correctly handles quoted paths with spaces.

## Feature: AWS CLI Strictness Mode

### Motivation

AWS CLI commands commonly carry `--flags` (e.g., `--region`, `--filters`, `--profile`) that are irrelevant to security classification. Only the service and operation verb (`aws ec2 describe-instances`) determine whether a command is read-only or modifying. Previously, unknown `--flags` could cause a command to be classified as `unknown` and require approval.

### Implementation

**`config.json`** — New top-level option:

```json
"modifying_strictness": "normal"
```

- **`"normal"`** (default): `--flags` and their values are stripped from AWS CLI commands before classification. Only `aws <service> <verb>` determines the decision.
- **`"strict"`**: Preserves current behavior — unknown flags may trigger `ask`.

**`src/ConfigLoader.ps1`** — Validates the option, defaults to `"normal"` if absent.

**`src/Resolver.ps1`** — New Step 0e tokenizes the command and strips all `--flag`, `--flag value`, and `--flag=value` patterns for the `aws_cli` domain when in normal mode:

| Input | Stripped to |
|-------|-------------|
| `aws --profile prod ec2 describe-instances --filters ...` | `aws ec2 describe-instances` |
| `aws ec2 --region us-east-1 describe-instances` | `aws ec2 describe-instances` |
| `aws ec2 terminate-instances --instance-ids i-123` | `aws ec2 terminate-instances` |

## Fix 3: Missing Trusted Pattern for docker exec comfyui

### Symptom

Five `TrustedPattern-Gate` tests failed because `docker exec comfyui ...` commands were not matching any trusted pattern.

### Root Cause

The trusted pattern for the `comfyui` container was never added to `config.json`. Only placeholder patterns (`^trusted_pattern$`, `^trusted_stuff\s+$`) existed.

### Fix

`config.json` — Added trusted pattern:

```json
"docker\\s+exec\\s+(?:-\\S+\\s+)?comfyui\\b"
```

This matches `docker exec comfyui <cmd>` and `docker exec -d comfyui <cmd>`, including across multi-line commands (via the existing `Singleline` regex option).
